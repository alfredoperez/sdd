Init Adoption Wizard

spec 023-init-adoption-wizard · PR 2 · builds on PR1 resolver + ADR 0002 · 2026-05-23

One line: Turn /sdd:init from a static scaffold into an incremental, idempotent wizard that adopts SDD on an existing repo one area at a time — survey → confirm a domain tree → AI-draft honest [DRAFT] requirement specs from the code surface → register them.

The flow

Phase 1 · scaffold (Layer 0)

Set up .sdd/ — kept as-is, idempotent

  • Create .sdd.json, .sdd/principles.md, .sdd/decisions/ when missing — never overwrite.
  • Principles: choose a blank template or AI-infer from lint/test/build config + CLAUDE.md + conventions (you confirm before it writes).
  • Already initialized? Skip straight to Phase 2.
Phase 2 · adopt an area (Layer 1) — NEW

Incremental — one area at a time, never the whole repo

a. cheap survey b. propose domain tree c. surface-first draft d. register
  • Survey manifests (package.json, nx.json, angular.json) + top-level folders → short list of candidate areas. You pick one (or type a path). No deep reading yet.
  • Propose a tree of domains (parent + leaves) — each with pattern / include+exclude / location / specPath / specFormat. Confirm, edit, or drop per node.
  • Draft the .spec.md requirements per leaf via parallel, token-capped subagents — surface-first (exports, routes, props, types, signatures).
  • Register — append domains to .sdd.json, write specs at resolved paths (via resolve-spec-paths.py). Only .spec.md is created; .arch.md/.coverage.md reserved.
Phase 3 · summary

What was created + next steps

  • List created files, flag that drafts need review, suggest /sdd:drift (now meaningful) and adopting more areas later.

Adopt another area anytime with /sdd:init.

Design principles

😊 Friendly

Clear step narration, choices via prompts (not walls of text), always skippable, encouraging "do it incrementally."

⚡ Efficient

Cheap survey before any deep read; one area at a time; parallel token-capped extraction; reuses the resolver; idempotent re-runs.

🔍 Honest

Every spec [DRAFT]; requirements tagged observed vs inferred; [NEEDS CLARIFICATION]; ## Uncovered. Never fabricates.

Scenarios

First-time adoptionPick checkout → survey, propose tree, draft [DRAFT] specs, write + register.
Always skippableDecline Phase 2 → init finishes after scaffold; no code analyzed.
Re-run adds, never clobbersAfter you review a spec (remove [DRAFT]), re-running leaves it untouched; only new areas added.
Honest draftsCan't infer a behavior → tagged inferred / [NEEDS CLARIFICATION]; unreadable files under ## Uncovered.
Already initialized.sdd.json + .sdd/ exist → open directly at Phase 2.

Out of scope

  • Whole-repo adoption in one pass (incremental only)
  • Generating/consuming .arch.md / .coverage.md tiers (separate spec)
  • Auto-migrating centralized specs to colocated
  • The standalone /sdd:grill interview skill (this wizard drafts; it doesn't interrogate)
